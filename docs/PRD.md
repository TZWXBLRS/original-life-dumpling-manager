# 禾也 HEYE 产品需求文档 (PRD)

## 1. 项目概述

**项目名称**：禾也 HEYE（手作素饺订购管理系统）

**项目目标**：构建一个面向顾客的冷冻饺子订购网站，同时支持后厨库存管理和管理员后台，实现从下单到配送/自取的全流程管理。

**设计规模**：高峰期每天销售不超过 100 盒饺子

**部署要求**：Docker 容器化部署，确保 7x24 不间断服务

---

## 2. 用户角色与权限

| 角色 | 权限范围 |
|------|----------|
| **顾客 (Customer)** | 浏览商品、查看库存、注册/登录、购物车、下单、查看历史订单、管理个人收货地址 |
| **后厨 (Kitchen Staff)** | 登录后台、查看订单列表、更新各口味饺子库存、查看预订数据用于生产计划 |
| **管理员 (Admin)** | 全部权限：用户管理、订单管理（确认/取消/发货）、库存管理、系统配置（自取地址/营业时间/活动价格） |

## 3. 产品目录与定价

### 3.1 饺子品类

| 分类 | 口味 | 单盒价格 |
|------|------|----------|
| **经典口味 (Classic)** | 荠菜、酸菜、三鲜、茴香、芹菜、玉米 | ¥33/盒 |
| **特色口味 (Specialty)** | 黑松露、菌菇 | ¥38/盒 |

### 3.2 促销优惠规则（系统自动计算最优组合）

#### 规则 A：经典饺子 - 买三赠一
- **4 盒经典 = ¥100**（已含打包费，相当于 3 盒的钱买 4 盒）
- 不足 4 盒按单价：1 盒 ¥33，2 盒 ¥66，3 盒 ¥99

#### 规则 B：特色饺子 - 三盒特惠
- **3 盒特色 = ¥100**（已含打包费）
- 不足 3 盒按单价：1 盒 ¥38，2 盒 ¥76

#### 规则 C：经典 + 特色混拼（4 盒起）
- **4 盒混拼 = 基础价 ¥100 + 特色盒数 × ¥10 差价**
- 示例：
  - 3 经典 + 1 特色 = 100 + 10 = ¥110
  - 2 经典 + 2 特色 = 100 + 20 = ¥120
  - 1 经典 + 3 特色 = 100 + 30 = ¥130

#### 规则 D：多盒叠加（>4 盒时系统自动计算最佳优惠）
- 每满一组按组合价，剩余部分按最优方式组合（优先使用对顾客最划算的规则）
- **示例 1**：5 盒经典 = 4 盒组合 (¥100) + 1 盒单价 (¥33) = **¥133**
- **示例 2**：4 盒特色 = 3 盒组合 (¥100) + 1 盒单价 (¥38) = **¥138**
- **示例 3**：4 特色 + 2 经典 = 4 盒混拼 (2 特 + 2 经 = ¥120) + 2 特色单价 (¥76) = **¥196**
- **示例 4**：4 经典 + 2 特色 = 4 经典组合 (¥100) + 2 特色单价 (¥76) = **¥176**

> **打包费说明**：所有价格已包含打包费，不再单独收取。

## 4. 配送方式

| 方式 | 费用说明 | 需要信息 |
|------|----------|----------|
| **自取 (Pickup)** | 免费 | 自取时间（在营业时间内选择） |
| **快递 (Delivery)** | 顾客自理运费 + 泡沫箱费 | 详细地址、姓名、手机号 |
| **闪送 (Express)** | 顾客自理运费（无泡沫箱费） | 详细地址、姓名、手机号 |

### 4.1 泡沫箱规则（仅快递需要）
- ¥5 / 个，每个可装 5 盒
- 计算方式：**向上取整 (总盒数 / 5) × 5 元**
- 示例：1-5 盒 → ¥5，6-10 盒 → ¥10，以此类推

### 4.2 自取配置（后台可修改）
- **自取地址**：后台设置固定地址
- **营业时间**：后台设置可自取时间段（如 10:00-20:00）
- **预约时间**：顾客选择自取日期和时间段

### 4.3 快递/闪送说明
- 运费由顾客自理（到付或联系商家确认）
- 网站仅计算并显示泡沫箱费用，实际运费不在网站内结算
- 必须填写：**收件人姓名、手机号、详细地址（省/市/区/街道/门牌号）**

### 4.4 冷冻发货规则（仅快递）

| 规则 | 说明 |
|------|------|
| **冷冻时间要求** | 冷冻饺子入库后必须冷冻满 **8 小时**才能发快递 |
| **发货时间窗口** | 快递发货时间仅限每天 **18:00 - 20:00** |
| **冷冻先于发货** | 发货时间不能早于冷冻完成时间（入库时间 + 8小时） |
| **前台确认机制** | 如果冷冻不足8小时需发货，系统提醒前台人员确认饺子实际冷冻情况后决定是否继续发货 |
| **无记录不可发** | 商品无冷冻入库记录时，无法发货 |

#### 冷冻确认流程（后台发货页面）
```
点击发货 → 系统检查各商品冷冻时间
  ├─ 全部达标 → 可直接发货
  ├─ 部分不足8小时 → 弹出确认提醒
  │   └─ 前台到冷库检查 → 确认已冻硬 → 继续发货
  └─ 有商品无记录 → 阻止发货，提示先入库
```

### 4.5 快递时效与风险提示

#### 京东快递送达时间查询
- 系统内置各省京东快递时效数据（次日达/隔日达/多日达）
- 顾客在购物车选择快递后，选择收货省份即可查询预计送达时间
- 后续可对接京东物流开放API获取实时时效

#### 运输保鲜限制
- 冷冻饺子在泡沫箱 + 冰袋条件下可安全保鲜约 **1 个晚上**
- 在途超过 1 晚（第 2 天及以后送达）→ 存在解冻变质风险

| 风险等级 | 条件 | 系统行为 |
|----------|------|----------|
| **SAFE** | 在途 ≤ 1 晚 | 正常下单，品质有保障 |
| **WARNING** | 在途 > 1 晚 | 建议取消订单；顾客坚持下单需勾选风险确认，自行承担损失 |
| **UNSUPPORTED** | 不支持地区 | 禁止快递下单，建议改用自取/闪送 |

#### 不支持快递的地区
海南、新疆、西藏（距离太远，超过保鲜期，快递一般无法支持）

## 5. 库存管理

### 5.1 库存展示
- **前台顾客端**：每个口味显示"库存 X 盒"，库存为 0 时显示"暂时缺货"并禁用加入购物车
- **后厨/管理员端**：可查看实时库存、今日预订量、剩余可售量

### 5.2 库存扣减逻辑
- **下单时**：锁定库存（不直接扣减）
- **订单支付后**：扣减实际库存
- **订单取消/超时未支付**：释放锁定库存
- **每日限购**：可配置每日总销量上限（默认 100 盒/天）

### 5.3 库存操作
- 后厨可通过后台增加/减少各口味库存（如入库、盘点调整）
- 记录库存变更日志（谁、什么时候、改了多少）

## 6. 订单流程

```
浏览商品 → 加入购物车 → 选择配送方式 → 填写信息 → 提交订单 → 模拟支付 → 后厨备餐 → 完成
```

### 6.1 订单状态流转

| 状态 | 说明 | 触发者 |
|------|------|--------|
| 待支付 | 订单已创建，等待支付 | 系统 |
| 已支付 | 支付成功，等待备餐 | 系统（支付回调） |
| 备餐中 | 后厨已确认，正在准备 | 后厨/管理员 |
| 待自取 | 自取订单已备好 | 后厨/管理员 |
| 配送中 | 快递/闪送已发出 | 管理员 |
| 已完成 | 顾客已取货/签收 | 系统/管理员 |
| 已取消 | 订单取消（未支付前可取消） | 顾客/管理员 |

### 6.2 在线支付
- **现阶段**：模拟支付（点击"支付"按钮直接跳转到支付成功状态）
- **后续**：预留微信支付 / 支付宝接口，有商户号后可直接接入

## 8. 技术方案

### 8.1 技术栈
| 层级 | 选型 | 说明 |
|------|------|------|
| **前端框架** | Next.js 14+ (App Router) | React 全栈框架，前后端一体，SSR 支持 |
| **UI 组件** | Tailwind CSS + shadcn/ui | 现代化、响应式、轻量 |
| **数据库** | SQLite + Prisma ORM | 单文件数据库，无需额外服务，部署简单；支持后续迁移到 MySQL/PostgreSQL |
| **认证** | NextAuth.js (Auth.js) | 支持账号密码登录，后续可扩展手机号验证码 |
| **部署** | Docker + Docker Compose | 容器化，一键部署，自动重启，保证不间断服务 |
| **进程守护** | Docker restart=always | 容器崩溃自动重启 |

### 8.3 数据库核心表
- **User**：用户表（id, 姓名, 手机号, 密码哈希, 角色, 状态）

- **SystemConfig**：系统配置表（自取地址, 营业时间, 每日限购等）

## 9. 非功能需求

### 9.1 不间断服务
- Docker 容器 `restart: always`，进程崩溃自动重启
- 数据文件挂载到宿主机 volume，容器重建数据不丢失
- 建议配置简单的健康检查

### 9.2 数据安全
- 密码使用 bcrypt 哈希存储
- 后台接口需要角色鉴权
- 表单输入做校验，防 SQL 注入（Prisma 天然防护）

### 9.3 响应式
- 适配手机、平板、桌面端

### 9.4 性能
- 高峰期日订单不超过 100 盒，SQLite 完全够用
- 静态资源 CDN 化（图片放在 public，后续可接对象存储）
